일정과 설정은 사용자 PC에 보관합니다.
선택한 외부 서비스와 PC가 직접 통신하며, ScheduleWidget 개발자에게 일정이나 연동 토큰을 전송하지 않습니다.

1. 기본 원칙

ScheduleWidget은 Windows PC에서 사용하는 일정 위젯입니다. 프로젝트 운영자는 GitHub 계정 rnrdus5642입니다. 이 방침은 현재 ScheduleWidget 앱과 이 소개 홈페이지에 적용됩니다.

  • 앱에는 사용자의 일정이나 계정 정보를 수집하는 개발자 서버가 없습니다. 개발자는 앱을 통해 사용자 PC의 일정, 파일, 토큰을 열람하지 않습니다.
  • 앱은 분석·광고 목적의 추적 정보나 오류 기록을 개발자에게 자동 전송하지 않습니다.
  • 외부 연동을 사용하면 해당 기능에 필요한 정보가 사용자 PC에서 해당 서비스로 직접 전송됩니다. 외부 서비스에서의 처리는 각 서비스의 방침도 적용됩니다.

2. PC에 보관하는 정보

일정 제목·날짜·시간·완료 여부, 앱 설정, 창 위치, 음악 재생목록, 연동 설정을 %LocalAppData%\ScheduleWidget 아래에 보관합니다. 일정과 설정 파일은 schedules.json이며 백업 파일도 생성됩니다.

  • 가져온 캐릭터 이미지와 설정은 같은 폴더 아래 Pet에 보관합니다.
  • 캐릭터 화면과 YouTube 플레이어의 WebView2 캐시·쿠키는 WebView2, WebView2Music 등에 보관합니다.
  • 오류와 캐릭터 복구 기록은 PC의 로그 파일에 남습니다. 크기 제한에 따라 이전 로그로 교체되며 자동으로 업로드하지 않습니다.
  • 구글 갱신 토큰과 텔레그램·카카오톡의 비밀 토큰 등은 현재 Windows 계정 범위의 DPAPI로 암호화합니다.

--demo 시연용 실행은 일정·로그인·캐릭터·내장 브라우저 캐시를 %LocalAppData%\ScheduleWidget.Demo에 별도로 저장합니다. 기존 데이터를 자동으로 가져오지 않으며, 로그인과 선택한 연동은 실제 서비스와 통신합니다. 기본 브라우저의 계정은 Windows 사용자와 공유되므로 시연 계정을 직접 선택해야 합니다. 일반 앱의 자동 시작 등록은 유지되며, 프로그램 제거 후에도 두 데이터 폴더는 남습니다.

3. 구글 계정 연동

구글 로그인은 사용자의 브라우저에서 진행합니다. 앱은 구글 계정의 비밀번호를 입력받거나 보관하지 않습니다. 로그인할 때 캘린더·Drive·이메일 권한을 함께 요청합니다. 이메일은 연결 계정 확인에 사용하며, 캘린더 동기화와 캐릭터 보관은 설정 → 연동 → 구글의 각 스위치가 켜져 있을 때 동작합니다. 처음에는 두 기능이 OFF이며, 이전에 켜 둔 선택은 재연결 후 이어질 수 있습니다. 스위치를 끄면 동기화가 중단되며 Google 권한 자체가 철회되지는 않습니다.

Google Calendar · 일정 동기화

요청 권한: calendar.events.owned

기본 캘린더의 일정을 읽어 표시하고, 위젯에서 일정을 추가·수정하면 구글에 반영합니다. 제목·날짜·시간·길이와 참석자 또는 다른 주최자가 있는지 등의 정보를 일정 표시와 동기화·삭제 범위 판단에 사용합니다. 반복 일정은 오늘부터 8주 이내의 날짜를 가져옵니다.

  • 앱이 만든 일정에는 앱 생성 여부와 완료 상태를 비공개 속성으로 기록합니다.
  • 위젯에서 삭제할 때 구글에서도 삭제하는 대상은 이 앱이 만든 참석자 없는 일정입니다. 구글에서 가져온 일정이나 참석자가 있는 일정은 구글에 남습니다.

Google Drive · 캐릭터 보관

요청 권한: drive.file

가져온 캐릭터의 이름·이미지 경로·동작 정의가 담긴 pet.json과 이미지를 ZIP으로 묶어 구글 드라이브의 ScheduleWidget 캐릭터 폴더에 보관합니다. 같은 계정의 다른 PC에서도 보관 옵션을 켜면 내려받습니다. 원본 폴더의 다른 파일과 PC별 크기·반전·표시·배치 설정은 보내지 않습니다. 현재 앱은 이 기능으로 만든 파일만 사용하며 다른 드라이브 파일을 탐색하지 않습니다. PC의 캐릭터 선택 화면에서 명시적으로 삭제한 캐릭터는 동기화할 때 드라이브에서도 삭제합니다.

이메일 · 연결 계정 확인

요청 권한: email / userinfo.email

어떤 계정이 연결되어 있는지 표시하고 계정 변경을 구분하는 데 이메일 주소를 사용합니다. 자동으로 로그인을 유지하기 위한 갱신 토큰은 사용자 PC에 암호화해 보관합니다.

구글 정보의 사용 범위

구글 API에서 받은 정보는 위 기능에 사용합니다. 개발자가 광고, 판매, 사용자 추적 또는 AI 모델 학습에 이용하지 않습니다. 사용자가 일정의 메시지 전송을 직접 선택하거나 알림을 설정하면 해당 일정 정보가 선택한 메시지 서비스에 전송될 수 있으며, 그 내용은 다음 항목에 설명합니다.

ScheduleWidget의 구글 사용자 데이터 사용은 Google API 서비스 사용자 데이터 정책과 그 제한적 사용 요구사항을 따릅니다.

4. 메시지와 마감 알림

설정 → 연동에서 서비스 정보를 입력하고 메시지를 보내거나, 설정 → 알림에서 전송 알림을 켠 경우에 사용합니다.

  • 텔레그램: 일정의 제목·날짜·시간 또는 직접 작성한 메시지를 Telegram Bot API로 전송합니다. 사용자가 지정한 Chat ID를 수신처로 사용합니다.
  • 카카오톡: 같은 종류의 내용을 카카오톡 메시지 API로 전송합니다. 수동 메시지는 나에게 또는 지정한 친구에게, 마감 알림은 나와의 채팅으로 보냅니다. 토큰이 만료되면 설정된 갱신 토큰으로 카카오 인증 서버에 갱신을 요청합니다.
  • 문자·전화: 문자 내용을 클립보드에 복사하고 Windows 휴대폰 연결 앱을 열거나, 전화번호의 tel: 링크를 실행합니다. 문자 전송은 연결 앱에서 사용자가 확인합니다.

텔레그램·카카오톡의 비밀 토큰은 암호화해 저장합니다. Chat ID, 카카오 REST API 키·웹 링크·친구 UUID, 전화번호는 PC의 설정 파일에 저장합니다.

5. 음악과 캐릭터

음악 파일과 YouTube

음악 파일의 경로와 재생목록은 사용자 PC에 저장합니다. 사용자가 YouTube 링크를 추가하면 영상·재생목록 제목을 확인하기 위해 YouTube 페이지와 oEmbed에 요청합니다. 이 과정에서 동의 쿠키를 함께 보낼 수 있으며, 앱에서 구글 로그인으로 받은 토큰을 YouTube 요청에 사용하지 않습니다.

YouTube 재생은 앱의 WebView2 안에서 YouTube 플레이어로 이루어집니다. YouTube가 처리하는 재생 정보·쿠키에는 Google 개인정보처리방침이 적용됩니다.

다른 앱의 재생 정보와 음량

달력의 음악 막대는 Windows가 제공하는 미디어 세션의 앱 이름·곡 제목·재생 상태·위치를 읽습니다. 재생 앱을 식별하기 위해 관련 창 제목과 프로세스 이름을 확인하고, Windows 오디오 세션으로 해당 앱의 음량을 읽거나 사용자의 조작을 전달합니다. 이 정보는 PC 안에서 처리하며 개발자 서버에 전송하지 않습니다.

캐릭터의 타이핑 반응

해당 동작을 선택한 캐릭터가 보일 때만 키가 눌렸다는 사실을 세어 애니메이션에 사용합니다. 어떤 키를 눌렀는지나 입력한 문장을 기록·저장·전송하지 않습니다. 캐릭터 파일은 구글 드라이브 보관을 켠 경우를 제외하면 PC에서 사용합니다.

6. 업데이트·도움말·홈페이지

캐릭터 추가 방법의 안내문과 제작 규격은 앱에 포함되어 있습니다. JSON·제작 요청문 복사는 사용자가 누르면 예시 텍스트를 PC 클립보드에 넣으며, 이미지 생성 서비스로 자동 전송하지 않습니다.

캐릭터 갤러리(codexpets.org), 서비스 도움말과 홈페이지는 사용자가 링크를 누를 때 기본 브라우저에서 엽니다. 일정·토큰·로컬 파일을 링크에 첨부하지 않으며, 해당 사이트의 접속 정보·쿠키 처리는 그 사이트와 브라우저의 방침을 따릅니다.

홈페이지의 설치 파일은 GitHub에서 내려받습니다. .NET Framework·WebView2가 없는 PC는 함께 담긴 Microsoft 공식 설치 프로그램이 Microsoft 서버에서 필요한 실행 환경을 받으며, 이 과정에는 Microsoft의 개인정보 처리방침이 적용됩니다. ScheduleWidget은 일정이나 연동 토큰을 전달하지 않습니다. 앱을 제거해도 일정과 설정은 재설치를 위해 남깁니다.

업데이트를 확인하거나 내려받을 때 GitHub의 프로젝트 배포 주소에 접속합니다. 이 요청에 일정이나 연동 토큰을 포함하지 않으며, 받은 업데이트는 서명을 확인합니다.

이 홈페이지는 GitHub Pages에서 제공하는 정적 페이지입니다. 자체 분석 도구, 광고, 로그인, 개인정보 입력 폼을 사용하지 않으며 자체 쿠키나 브라우저 저장소를 생성하지 않습니다. GitHub는 서비스 보안을 위해 방문자의 IP 주소 등 접속 정보를 처리할 수 있습니다. 자세한 사항은 GitHub 개인정보처리방침을 확인해 주세요.

7. 보관 기간·연동 해제·삭제

일정과 설정, 가져온 파일은 사용자가 삭제할 때까지 PC에 보관합니다. 기능을 끄거나 구글에서 로그아웃해도 이미 PC에 저장된 일정과 캐릭터는 남습니다. 각 외부 서비스에 보낸 데이터의 보관·삭제는 해당 서비스의 설정과 방침을 따릅니다.

  • 구글 연결 해제: 설정의 로그아웃으로 현재 앱의 구글 작업을 취소하고 권한 해제와 로컬 로그인 정보 삭제를 시도합니다. 네트워크나 파일 저장에 실패하면 안내하며, 저장 실패는 경고의 다시 저장으로 재시도할 수 있습니다. 구글 계정의 타사 앱 연결에서도 권한을 해제할 수 있습니다.
  • 텔레그램·카카오톡: 연동 설정에서 토큰을 비우고 저장합니다. 카카오 계정의 연결된 서비스에서도 앱 연결을 해제할 수 있습니다.
  • PC의 모든 앱 데이터: 앱을 종료하고 %LocalAppData%\ScheduleWidget 폴더를 삭제하면 일정·설정·백업·가져온 캐릭터·웹 플레이어 캐시 등 해당 폴더의 데이터가 삭제됩니다.
  • 외부에 보낸 데이터: PC 데이터를 삭제해도 구글 캘린더·드라이브나 메시지 서비스의 데이터가 함께 삭제되지는 않습니다. 해당 서비스에서 별도로 삭제할 수 있습니다.

8. 문의와 변경 안내

기능과 개인정보 처리에 관한 문의는 ScheduleWidget GitHub 이슈로 전달해 주세요. 공개 이슈에는 일정 원문, 토큰 등 개인 정보를 첨부하지 않아도 됩니다.

처리하는 정보나 기능이 바뀌면 이 페이지와 저장소의 개인정보처리방침을 갱신하고 최종 수정일을 표시합니다.

English summary

ScheduleWidget is a Windows desktop schedule widget maintained by rnrdus5642. Schedules, settings, imported character files and credentials stay on the user's PC. The app has no developer-operated data collection server and does not send analytics, advertising identifiers or automatic error reports to the developer.

Google sign-in runs in the browser and requests the three declared scopes together. Calendar and Drive switches control subsequent synchronization: both are initially off, and existing enabled preferences may resume after reconnection. Turning a switch off does not revoke the Google grant. Calendar access (calendar.events.owned) synchronizes primary-calendar events. Deletions on Google are limited to attendee-free events created by the app. Drive access (drive.file) stores and retrieves ZIP packages containing character manifests and images using app-created files. Unrelated source-folder files and per-PC size, placement, visibility and flip settings are excluded; each PC must enable character storage. The account email identifies the connected account. Refresh tokens are encrypted using Windows DPAPI. Google data is used for the described features, not advertising, sale, tracking or AI model training. Use of Google API data adheres to the Google API Services User Data Policy, including Limited Use requirements.

User-enabled Telegram and Kakao messages and reminders send schedule details or composed text directly to the chosen service. YouTube content is played through its embedded player. Windows media information, volume controls and typing reactions are processed locally. Typing reactions count key presses without recording keys or typed text. Installers and updates are retrieved from GitHub. When runtimes are missing, official Microsoft bootstrappers download .NET Framework or WebView2 from Microsoft under its privacy practices; ScheduleWidget does not pass schedules or credentials to them. Uninstalling the app retains local user data. The creation guide is bundled locally; its copy buttons put example text on the clipboard when clicked. Gallery and help links open in the user's browser without attaching schedules, credentials or local files, and those sites apply their own privacy practices.

The optional --demo launch stores a separate profile in %LocalAppData%\ScheduleWidget.Demo without importing normal schedules or credentials. It uses real Google APIs; the system browser account session remains shared with the Windows user. Both profiles survive program uninstall. Local data remains until deleted by the user. Google can be disconnected in the app or through Google Account connections; other service credentials can be cleared in settings. Closing the app and deleting its LocalAppData folder removes local files and backups, but not copies sent to external services. This website has no custom tracking scripts or forms; GitHub Pages may process visitor IP addresses for security. Contact: project issues.
